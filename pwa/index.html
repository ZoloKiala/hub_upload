How to use this app

      
    

    


      
This app puts files into a repository on the Hugging Face Hub,
        under the IWMIHQ organization, in one commit. It never
        deletes anything.


      
Before you start

      
    
        
  • You need your own Hugging Face account, added to IWMIHQ
          with write access — ask an admin.
    • 
        
  • And a write token from that account
          (huggingface.co/settings/tokens).
          A read-only one is refused when you connect rather than at the end of an
          upload.
    • 
        
  • The token stays in this browser. Nothing is sent anywhere except
          huggingface.co, and Sign out removes it.
    • 
      


      
The five steps

      
    
        
  1. Choose a type. A Model holds weights, a
          Dataset holds data, a Space holds an app — and a Space also
          asks which SDK runs it (Gradio, Streamlit, Docker or static).
    2. 
        
  2. Create new, or update existing. Creating asks for a name
          under IWMIHQ/, whether it is public or private, and a licence.
          Updating lists what is already there — including private repositories your
          account can see — and adds your files to one of them.
    3. 
        
  3. Add files. Drag them in, browse for files or a whole
          folder, or import from a public GitHub repository. Folder structure is kept,
          so data/2024/eta.tif arrives at that path.
    4. 
        
  4. Read the checks and the README. Both update as you type.
          A warning is not a blocker: it is something to look at before you commit.
    5. 
        
  5. Upload to Hub. One commit, with a progress bar and a log.
          Keep the window open until it finishes.
    6. 
      


      
What it does with your files

      
    
        
  • Large files go via git LFS automatically — anything over
          10 MB is marked LFS in the staged list. You do
          not have to configure anything, but those uploads take longer.
    • 
        
  • A README.md is generated and committed with them. It
          carries the licence, your tags and the Space SDK as front matter, then the
          description, your name, and the list of files. If the repository already has
          a README, this replaces it — copy anything worth keeping into the
          description first.
    • 
        
  • Nothing else in the repository is touched. Updating adds
          or replaces the paths you staged; other files stay as they are.
    • 
        
  • The commit message is what you typed, or "Add files via
          Hub uploader" with your name. It is what people see in the repository's
          history, so a sentence beats a filename.
    • 
      


      
Importing from GitHub

      
Give it owner/repo or a full GitHub URL. It stages the first
        25 files under 5 MB from the default branch, keeping their
        paths — enough for code and configuration, not for data. Public repositories
        only; it does not ask GitHub for a token.


      
After the upload

      
    
        
  • History lists what you uploaded from this device
          — the last 25, kept in this browser. It is not an organization-wide log.
    • 
        
  • Projects lists everything IWMIHQ has published, plus
          private repositories your account can see. The search box filters by name,
          by kind ("space"), or by visibility ("private"), and every word has to
          match.
    • 
        
  • The Hub takes a few minutes to build a Space and to render a dataset
          preview. A repository that looks empty immediately after an upload is
          usually still processing.
    • 
      


      
When something goes wrong

      
    
        
  • "That token is read-only." Make a new token with the
          write role; you cannot upgrade an existing one.
    • 
        
  • 401 or 403 on upload. The token was revoked, or your
          account is not a member of IWMIHQ with write access.
    • 
        
  • The repository already exists. Creating one that is
          already there is not an error — it uploads into the existing repository and
          says so in the log.
    • 
        
  • The upload failed halfway. A commit either lands or it
          does not; a failed one leaves the repository as it was. Fix what the message
          says and press upload again.
    • 
        
  • It is slow. Large files and many files both cost time, and
          the whole upload runs from this browser — closing the window stops it. The
          app warns before you leave with an upload running.
    • 
      


      
The app itself

      
    
        
  • Install it and it opens in its own window: the install
          icon in the address bar on Chrome or Edge, Share → Add to Dock on Safari.
    • 
        
  • It works offline up to the point of uploading — staging
          files, the checks and the README all happen here. Only the upload needs the
          network.
    • 
        
  • Light or dark is the sun/moon toggle in the bar; until you
          choose, it follows your system.

Install this app

      
    

    

      
Chrome or Edge on desktop: click the install icon at the right of the address bar,
        or open the browser menu and choose “Install Hub uploader”.

      
Safari on iPadOS/macOS: use Share → Add to Dock. Once installed, this app opens in
        its own window with no browser chrome, and works offline until you upload.
